# Тест-план: Microfinance IS

Ответственный: Issabekov Galymzhan (Testing, Analytics & Integration).
Версия прототипа: ветка `main` после добавления JWT-авторизации, проверки лица и платежей (папка `mfo-prototype/`).

## 1. Цель и объём

Проверить, что прототип правильно применяет бизнес-правила кредитования, корректно
отвечает на неверные данные, а API и Telegram-бот работают с одной базой согласованно.

В объёме: `app/services/approval.py` (правила), REST API (`app/api/`), БД (`app/db/database.py`),
отчёты (`app/services/analytics.py`), сервисный слой Telegram (`bot/service.py`).
Вне объёма: нагрузочное тестирование, реальный Telegram Bot API (в тестах он замокан),
визуальная проверка HTML-шаблонов.

## 2. Окружение и запуск

Python 3.12, зависимости из `requirements.txt`. Тесты используют временную БД и временную
папку логов (`tests/conftest.py`), боевой `mfo.db` не затрагивается.

```
cd mfo-prototype
pip install -r requirements.txt
pytest                                   # все тесты
pytest tests/test_boundaries.py -v       # одна группа
pip install pytest-cov                   # один раз
pytest --cov=app.services --cov=app.db --cov=app.api \
       --cov=bot.service --cov-report=term-missing
```

## 4. Тест-кейсы (новые)

В коде идентификаторы стоят в комментариях; один ID может покрывать несколько параметров.

### 4.1 Граничные значения (`test_boundaries.py`)

| ID | Проверка | Ожидание |
|---|---|---|
| BV-01..03 | Сумма 499 999,99 / 500 000 / 500 000,01 / 500 001 | Первые две: `Approved/Auto`. Выше лимита: `Pending Admin Review/Manual` |
| BV-04..06 | Платёж ровно 40% дохода, на 1 KZT ниже, выше | Равно или выше: `Approved`. Ниже: `Rejected` |
| BV-07..08 | Срок 1 и 120 месяцев | Правило 40% работает на краях срока |
| BV-09..13 | Возраст: день рождения сегодня, завтра, вчера, 29 февраля | 18 лет исполнилось: `PASS`. Завтра 18: `FAIL` |
| BV-14..18 | ИИН: 11 и 13 цифр, буква, пусто, `None`, пробел | `FAIL`; ровно 12 цифр: `PASS` |
| BV-19 | Проверка `AMOUNT_LIMIT` совпадает с правилом решения | `PASS` на 500 000, `MANUAL_REVIEW` выше |
| BV-20..26 | График: 1 месяц, переход через год, день 29-31, монотонность дат, округление, сумма аннуитета | См. тесты |

## 7. Ограничения

- Реальный Telegram Bot API не вызывается; бот тестируется через мок (`MockSession`) и сервисный слой.
- Проверка лица тестируется на подменённом движке (`fake_engine`): логика живости и одноразовых токенов проверена, но настоящая веб-камера и распечатанное фото на реальном устройстве не проверялись.
- Деньги хранятся как `REAL`, поэтому сравнения сумм в тестах учитывают округление до 2 знаков.
- `max_affordable_payment` считается без процентов (правило из требований), а график платежей аннуитетный с 24%. Реальный платёж по графику выше, чем в проверке на 40%. Стоит уточнить это у аналитика требований.
