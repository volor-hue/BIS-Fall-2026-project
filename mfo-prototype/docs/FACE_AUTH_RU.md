# Проверка лица (Computer Vision) — объяснение для защиты

## Что делает
Клиент при регистрации загружает фото 3x4 (поле «Photo 3x4»). Оно сохраняется в `uploads/`, а в таблицу
`documents` пишется строка с `doc_type = "face"`.
Когда клиент подаёт заявку на кредит, его сначала отправляют на страницу `/face`: браузер включает веб-камеру,
делает снимок и отправляет его на `POST /api/face/verify`. Сервер сравнивает лицо со снимка с лицом на фото 3x4:
```json
{"match": true, "score": 0.82, "threshold": 0.363, "reason": "same person",
 "face_token": "...", "face_token_expires_in": 300}
```

## Гейт перед заявкой на кредит
Клиент **не может** подать заявку без успешной проверки лица. Это проверяет **сервер**, а не только браузер.

1. На dashboard клиент нажимает **Submit application**: форма сохраняется в `sessionStorage`, браузер переходит на `/face?next=apply`.
2. Клиент делает снимок, и браузер отправляет его на `POST /api/face/verify`.
3. Если `match=false`, заявка **не** отправляется, показывается причина, снимок можно повторить.
4. Если `match=true`, сервер выдаёт одноразовый `face_token`: случайная строка (`secrets.token_urlsafe`), живёт 5 минут
   (`FACE_TOKEN_MINUTES`). В таблице `face_tokens` хранится только её SHA-256, сам токен в БД и в логах не лежит.
5. Страница `/face` сама вызывает `POST /api/applications` с сохранённой формой и `face_token`.
6. Сервер «гасит» токен (`used_at`), и дальше работает прежняя логика: Auto Approved / Rejected / Pending Admin Review.

Без токена, с чужим, просроченным или уже использованным токеном ответ **403**.
**Исключение:** сотрудник, который заводит заявку за клиента в офисе, проверку лица не проходит.

Почему проверка на сервере: если бы браузер сам решал «лицо совпало → отправить», любой мог бы отправить
`POST /api/applications` напрямую (через Swagger или curl) и обойти камеру.

## Как работает распознавание лица (простыми словами)
1. **Детекция.** Нейросеть **YuNet** находит на картинке прямоугольник с лицом и 5 точек: 2 глаза, нос, 2 уголка рта.
   Если лица нет, ответ `"no face found"`; если лиц несколько, `"2 faces found ..."`.
2. **Выравнивание (alignment).** По этим точкам лицо поворачивается и вырезается в квадрат 112×112 (`alignCrop`),
   чтобы наклон головы не мешал.
3. **Эмбеддинг.** Нейросеть **SFace** превращает лицо в **вектор из 128 чисел**, «цифровой отпечаток» лица.
   Сеть обучена так, что у одного человека векторы похожи, а у разных людей нет.
4. **Сравнение.** Считаем **косинусное сходство** двух векторов (1 = одинаковые, около 0 = непохожие).
   Если `score >= 0.363` (порог, который рекомендуют авторы SFace), это тот же человек.

## Почему OpenCV (YuNet + SFace)
- `opencv-python` ставится одной командой `pip install` на Windows, macOS и Linux. Библиотеке `face_recognition`
  нужен `dlib`, а его на Windows приходится собирать через CMake/Visual Studio.
- Модели — два ONNX-файла из официального OpenCV Model Zoo (~38 МБ). Они скачиваются сами в `models/` при первом
  запуске (`python run.py`) и в git не попадают. Работает на CPU, одно сравнение примерно 0.1 с.

## Логи и защита от спама
- В `logs/audit.log` пишутся `event=face_verify ... match=True score=0.83` и `event=face_gate_denied reason=no_token|bad_token`.
  Сам снимок и токен в лог **не** пишутся (биометрия).
- `POST /api/face/verify` ограничен тем же лимитом, что подача заявки: `MFO_RATE_LIMIT_SUBMIT` (по умолчанию 10 в минуту с IP).

## Настройки (`.env`)
| Переменная | По умолчанию | Что значит |
|---|---|---|
| `FACE_THRESHOLD` | `0.363` | порог сходства; выше = строже (меньше чужих пройдёт, но чаще не узнает своего) |
| `FACE_TOKEN_MINUTES` | `5` | сколько живёт одноразовый `face_token` |
| `FACE_MODEL_DIR` | `models` | куда скачивать модели |

## Как тестировали
- `pytest`: `tests/test_face.py` проверяет логику без настоящих фото — `face_verify.verify` подменяется заглушкой:
  заявка без токена → 403, совпадение → токен, токен одноразовый, просроченный/чужой/выдуманный → 403,
  несовпадение → токена нет, сотрудник без проверки, без входа → 401, сотрудник на `/face/verify` → 403,
  не JPG/PNG → 400, нет фото 3x4 → 404, base64-вариант, запись в audit-лог, регистрация с фото 3x4.
- Вручную (настоящие модели): два разных фото одного человека дали score ≈ 0.83 (match), фото двух разных людей ≈ 0.19 (no match).
  Для защиты: прогнать на своём фото 3x4 и веб-камере и записать свои score.

## Риски и ограничения
- **Спуфинг:** камере можно показать фото или видео человека — нет проверки «живости» (liveness).
- **Свет, очки, маска, старое фото** снижают score, возможен ложный отказ.
- **Приватность:** фото лица — биометрические персональные данные (Закон РК «О персональных данных»). Нужно согласие
  пользователя; снимки с камеры не сохраняем, в лог пишем только match/score.
- Порог взят из статьи авторов SFace, на нашей выборке не калибровался.

## Следующая измеримая задача
Liveness-проверка: пользователь моргает или поворачивает голову, браузер шлёт 3–5 кадров, сервер проверяет,
что точки YuNet сдвигаются между кадрами. Показать, что фото с телефона не проходит, а живой человек проходит, и добавить тест.

## Telegram и face-гейт
Бот **не создаёт** заявки (только статус, график и поиск сотрудником), поэтому обойти проверку лица через Telegram нельзя.
