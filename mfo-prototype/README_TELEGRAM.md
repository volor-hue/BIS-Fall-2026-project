# Telegram-бот клиента (вариант до авторизации API)

Это дополнение к учебному прототипу Microfinance IS **до** задач по JWT, Redis и защите API.
База кода: коммит `62dd5f2f9e4840b3742dcbdd69e12d9da26184ef` (короткий `62dd5f2`), последний из пяти коммитов загрузки прототипа (`315b51d`, `821a240`, `37c56d7`, `130bfc9`, `62dd5f2`).

Бот на **aiogram 3** читает **ту же** SQLite-базу, что и сайт. Новые таблицы только добавляются. Заявки, правило одобрения, график, страницы и 18 операций API не менялись.

Живой Telegram этим архивом **не проверялся**: токена нет, сообщения в Telegram не отправлялись. Тесты подменяют транспорт Bot API.

## Простой запуск одной командой

Обновление не требует новой базы и нового токена. Оставьте свои `mfo.db` и `.env`. В `.env` уже должен быть `TELEGRAM_BOT_TOKEN`. Строку с токеном не перезаписывайте.

Из каталога `mfo-prototype`, в том же виртуальном окружении, где стоят зависимости:

```bash
python run.py
```

Команда читает `.env` рядом с `run.py` (текущая папка терминала не важна), превращает `MFO_DB` в один абсолютный путь и отдаёт его и сайту, и боту. Если `MFO_DB` не задан, оба используют файл `mfo.db` в каталоге проекта. Сайт открывается на **http://127.0.0.1:8001** — порт 8000 часто занят. Другой порт: `MFO_PORT=8002 python run.py`. Если порт занят, команда напишет об этом и не оставит бота работать в фоне.

Окно терминала должно оставаться открытым: в нём живут оба процесса. `Ctrl+C` останавливает и сайт, и бота. Если один из них завершится сам, второй тоже будет остановлен.

Сотруднику код привязки не нужен.

1. Пока список сотрудников пуст, бот для клиентов уже работает, а `/find` никому ничего не показывает.
2. Узнать свой числовой id: `python run.py --bot-only`, открыть личный чат с ботом, отправить `/whoami`. В ответе только ваш id. Остановить: `Ctrl+C`.
3. Дописать этот id в `.env`, не трогая токен:

```bash
MFO_TELEGRAM_STAFF_IDS=100000001
```

Число `100000001` — образец. Подставьте id из `/whoami`. Несколько человек: `100000001,100000002`. Имя и `@username` не подходят. Ошибочная строка отключает поиск целиком.

4. Снова `python run.py`.
5. В личном чате сотрудника: `/find Нурбек` или просто сообщение `Нурбек`. Бот покажет кнопки. У одинаковых имён разные номера клиентов. Нажатие открывает заявки и график только для чтения: одобрить, отказать и отметить платёж из бота нельзя.

Клиент по-прежнему привязывается кодом `/link` и видит только свои заявки. Чужой callback ему не отдаёт данные.

## Это не production

Веб-прототип специально оставлен в состоянии «до security»:

- REST API открыт, без входа;
- id клиента и сотрудника лежат в обычной cookie;
- пароли — SHA-256 без соли.

Привязка Telegram **не закрывает** эти дыры. Она защищает только канал бота.

Команды `telegram_operator.py` локальные. Отдельного HTTP-метода, который выдаёт код, нет. Кто может запустить этот файл и прочитать `mfo.db`, тот может выписать код и привязать свой Telegram к клиенту. Ограничьте учётную запись компьютера и права на файл базы. Не выкладывайте CLI в общий хостинг и не проксируйте его в веб.

## Что умеет бот

Только личный чат. Язык ответов — русский.

- `/start` — справка о привязке. Любой аргумент (`/start 1`, `/start 15`, код) **игнорируется**: записи не показываются и код не тратится.
- `/help` — список команд.
- `/link КОД` — один раз привязать этот Telegram к клиенту.
- `/unlink` — отвязать только свой Telegram.
- `/status` (то же `/applications`) — свои заявки и статусы.
- `/app НОМЕР` — одна своя заявка и автопроверки.
- `/schedule` (то же `/payments`) — графики своих кредитов.
- `/loan НОМЕР` — график одного своего кредита.
- `/whoami` — только ваш числовой Telegram id. Работает и до настройки списка сотрудников, чужие данные не открывает.
- `/find ИМЯ` — только id из `MFO_TELEGRAM_STAFF_IDS`, только личный чат: поиск по имени и просмотр заявок и графика. Оплата и решение по заявке не меняются.

Кнопки под списком заявок открывают те же данные. Чужой `application_id` или `loan_id` (в том числе подмена callback) отвечает отказом и не показывает сумму, цель и имя другого клиента.

Бот **не** принимает платежи, не меняет статус `repayments` и не показывает ИИН, паспорт, телефон, почту, адрес и пароль. В чат не попадают данные карты: в прототипе их и нет.

Уведомления «вам одобрили заявку» **не** делались. Для них нужен либо фоновый обход базы с живым токеном, либо встройка в обработчики сайта. Второе меняло бы путь заявки в ещё открытом API, поэтому клиент сам запрашивает статус командой.

## Одна база

И сайт, и бот открывают файл из переменной `MFO_DB` (если её нет — `mfo.db` в текущей папке). Задайте **один абсолютный путь** обоим процессам.

Сайт читает переменную в момент импорта `database.py` и **не** читает `.env`. Бот и `telegram_operator.py` перед работой читают окружение и файл `.env` (уже заданная переменная процесса важнее файла).

```bash
cd mfo-prototype
export MFO_DB="/absolute/path/to/mfo-prototype/mfo.db"
```

Таблицы Telegram создаёт тот же `database.init_db()` при старте сайта или бота. Повторный запуск безопасен для уже заполненной базы: `CREATE TABLE IF NOT EXISTS`, строки клиентов и заявок не удаляются. Отдельной второй базы нет.

Новые таблицы (к бизнес-ERD не относятся):

| Таблица | Связь |
|---------|--------|
| `telegram_links` | один клиент — один Telegram user id, `ON DELETE CASCADE` |
| `telegram_pairing_codes` | коды клиента, в базе только SHA-256, `ON DELETE CASCADE` |
| `telegram_link_attempts` | неудачные попытки по числовому Telegram user id |

## Токен

1. В Telegram откройте `@BotFather`.
2. Отправьте `/newbot`, задайте имя и username.
3. BotFather пришлёт токен вида `123456789:AA...`.
4. Локально скопируйте `.env.example` в `.env` и подставьте токен вместо `PUT_YOUR_TOKEN_HERE`.
5. Не коммитьте `.env`, не вставляйте токен в чат и не кладите его в архив.

В этом проекте токена нет. Пока в `.env` стоит образец, `python telegram_bot.py` завершится с кодом 2 и к Telegram не подключится.

## Установка и запуск

Нужен Python 3.10+ (проверка этой сборки — Python 3.12.3). Зависимости закреплены в `requirements.txt`: FastAPI `0.162.2`, uvicorn `0.54.0`, Jinja2 `3.1.6`, python-multipart `0.0.33`, Pydantic `2.13.5`, pytest `9.2.0`, httpx `0.28.1`, aiogram `3.31.0`. aiogram сам ставит aiohttp.

```bash
cd mfo-prototype
python3 -m venv venv
source venv/bin/activate          # Windows: venv\Scripts\activate
pip install -r requirements.txt
export MFO_DB="$(pwd)/mfo.db"     # лучше абсолютный путь, как в примере выше
```

Сайт (как в `README_RUN.md`), в первом терминале:

```bash
export MFO_DB="/absolute/path/to/mfo-prototype/mfo.db"
uvicorn main:app --host 127.0.0.1 --port 8000
```

Бот, во втором терминале, с тем же `MFO_DB` и токеном в `.env` или в окружении:

```bash
export MFO_DB="/absolute/path/to/mfo-prototype/mfo.db"
python telegram_bot.py
```

Бот ходит в Telegram исходящим long polling (`start_polling`). Webhook и открытый HTTPS не нужны. Остановка: `Ctrl+C`.

## Сценарий оператора и клиента

1. Поднимите сайт и заведите клиента через `/register` или `POST /api/clients`. Запомните `client_id`. Заявка на 400 000 на 12 месяцев при доходе 300 000 по-прежнему даёт **Approved / Auto** и график.
2. На машине с базой, не через сайт:

```bash
export MFO_DB="/absolute/path/to/mfo-prototype/mfo.db"
python telegram_operator.py issue --client-id 1
```

Команда один раз печатает код `XXXX-XXXX`, id и имя. ИИН, телефон, почта и паспорт не печатаются. В базе лежит только хеш. Пока клиент привязан, новый код не выдаётся: сначала `unlink`.

3. Клиент в **личном** чате с ботом (не в группе):

```text
/link AB3D-EF7H
/status
/app 1
/schedule
/loan 1
```

4. Проверка привязки без показа кода:

```bash
python telegram_operator.py status --client-id 1
```

5. Отвязка со стороны клиента: `/unlink`. Со стороны оператора:

```bash
python telegram_operator.py unlink --client-id 1
```

Отвязка также гасит ещё не использованные коды этого клиента. После этого для новой привязки нужен новый `issue`. Для сотрудника этот код не нужен: ему достаточно своего id в `MFO_TELEGRAM_STAFF_IDS`.

Поиск `/find` проверяет числовой id на каждом сообщении и на каждой кнопке, в том числе если callback подменили или переслали. Пустой список и любая нечисловая запись закрывают поиск. Группы молчат. Клиент без id в списке по-прежнему видит только свои заявки.

## Как устроена привязка

- Код: 8 символов из алфавита без `0/O/1/I` (около 2^40 вариантов), на экране `XXXX-XXXX`. Срок по умолчанию 10 минут (`MFO_TELEGRAM_CODE_TTL_SECONDS`, от 30 до 86400).
- В SQLite пишется SHA-256 нормализованного кода. Это отпечаток, не парольный KDF. Онлайн-подбор режется лимитом; офлайн-подбор имеет смысл только тому, кто уже скопировал файл базы, а в этом прототипе в файле и так лежат клиенты.
- Новый `issue` в той же транзакции помечает старые неиспользованные коды клиента использованными.
- Успешный `/link` в транзакции `BEGIN IMMEDIATE` помечает код использованным и вставляет строку связи. Повтор, второй поток и второй пользователь этот код больше не принимают.
- Один клиент — один Telegram user id, и наоборот (`UNIQUE`).
- Чужой пользователь, уже привязанный Telegram и группа код клиента не «открывают». Групповой чат код не сжигает.
- Неудачные попытки: 5 на один Telegram user id и 100 на всех за 15 минут. На время блокировки даже верный код не принимается и не сжигается. Пустой `/link` попыткой не считается.
- Все выборки с `?`. Заявка и график читаются только при `client_id` привязанного пользователя. Тексты из базы экранируются для HTML.
- В журнал пишутся user id и причина отказа, не код, не ИИН и не контакты. Журнал aiogram в боевом запуске опущен до WARNING, чтобы не печатать текст апдейта.

## Тесты

Из каталога `mfo-prototype` при активированном venv:

```bash
pytest
```

Исходные тесты прототипа (`tests/test_approval.py`, `tests/test_api.py`) остаются. Новые — `tests/test_telegram.py`: временная база, mock-сессия aiogram, гонка двух потоков, просрочка, повтор кода, лимит попыток, группа, подмена callback. Сеть Telegram не используется.

На сборке этого архива: **50 passed** (24 прежних теста прототипа, 18 в `tests/test_telegram.py`, 8 в `tests/test_staff_launcher.py`). То же число записано в `TELEGRAM_MANIFEST.txt`.

## Ограничения

- Нет push-уведомлений и нет оплаты через бота.
- Нет входа в сам веб-API: это сознательно прежний прототип.
- CLI оператора без пароля; защита — доступ к машине и к файлу базы.
- Привязка доверяет числовому id, который присылает Telegram. Подменить его можно, только говоря с ботом от другого аккаунта или подменив ответы Bot API.
- Долгий график режется на несколько сообщений (лимит Telegram — 4096 символов).
- Эта копия не подключалась к BotFather и не отправляла реальных сообщений.
